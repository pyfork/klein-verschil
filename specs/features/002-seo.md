# 002: SEO (technical build spec)

Must-have for launch. Everything below is a launch requirement unless it's marked "later".

- Site: `https://property.puascari.com`, English only at launch (`en-MY`). Malay is parked.
- Builds on Part D of the media and location developer spec (the mocks package) and replaces that spec's open decision on structured data scope.
- References to "dev spec" below mean that developer spec.

### 1. Rendering

- All public pages are server-rendered or pre-rendered. The title, meta description, H1, price, facts, captions, nearby rows and listing text must be in the first HTML response. No client-only rendering for public content.
- Pages must work with JavaScript turned off, at least to read them.
- One H1 per page. Headings follow page structure and are never used for styling.

### 2. URLs

- Lowercase, hyphenated, stable, and readable. English is at the root, with no language prefix:
  - Listing: `/rent/{state}/{area}/{slug}-{id}`, for example `/rent/selangor/petaling-jaya/3-bedroom-terrace-ss2-a7k2p`
  - Area: `/rent/{state}/{area}`
  - Near: `/rent/near/{poi-slug}`
  - Reserved for Malay later (parked): `/ms/sewa/...`. Don't use the `/ms/` prefix for anything else.
- The `{id}` sets the canonical. If the slug changes, 301 to the current slug.
- One canonical per page. Self-referencing canonical on every indexable page.
- Trailing-slash policy is chosen once and enforced with 301s. HTTPS only.
- **Host:** `property.puascari.com` is the only indexable host.
  - `puascari.com/sewarumah` and `puascari.com/sewarumah/*` return a 301 (permanent) to `https://property.puascari.com/`, keeping the path after `/sewarumah` where one exists. Use 301, never 302, so Google passes the link value along.
  - `www.property.puascari.com` and `http://` versions return a 301 to `https://property.puascari.com`.
  - Because `.com` isn't tied to a country, Malaysian targeting comes from `<html lang="en-MY">`, Malaysian content and addresses, prices in MYR, and Malaysian links. `hreflang` is added once Malay launches. Search Console no longer has a country-targeting setting.
  - `property.puascari.com` gets its own Search Console property. Also add a Domain property for `puascari.com` to see both together.

### 3. Languages

- **Launch: English only.** `<html lang="en-MY">` on every page. No `hreflang` tags yet, because they need at least two language versions.
- All platform text (labels, facts, the summary sentence, page titles) goes through the translation layer from day one, even with only English filled in. Adding Malay later then means adding text, not rewriting pages.
- Owner-written text (descriptions, notes) is shown as written, in any language. Don't machine-translate it into indexable content.
- **When Malay is unparked:** separate URLs under `/ms/`, never mixed languages on one page. `hreflang` reciprocal on every page (`en-MY`, `ms-MY`, `x-default` pointing to English), also listed in the sitemap.

### 4. Indexing control

| Page | Index? | Notes |
|---|---|---|
| Live listing | Yes | In sitemap |
| Rented, under 90 days | Yes | Out of sitemap, "Rented" banner, similar homes block |
| Rented, 90 days or more | `noindex, follow` | Indexable again when relisted |
| Deleted listing | 410 | |
| Draft or preview (`?preview=`) | `noindex`, plus auth | Never linked publicly |
| Area or near page with at least N live listings | Yes | N starts at 5 (dev spec D3) |
| Area or near page with fewer than N | `noindex, follow` | Out of sitemap |
| Search results with filters | `noindex, follow` | Canonical to the clean area page. Filter params are never put in internal links as crawlable `<a href>` beyond a short allowlist. |
| Paginated area pages | Yes | Self-canonical per page, no `rel=prev/next` dependency |
| Account, owner dashboard, leads, tenancy record, payments | Blocked | `noindex` plus auth. Disallowed in robots.txt. Never in sitemap. |

- `robots.txt` disallows `/account/`, `/owner/`, `/api/`, `/tenancy/` and internal search parameters. It references the sitemap index.
- Staging and preview hosts: `noindex` header on every response, plus HTTP auth.

### 5. Sitemaps

- Sitemap index plus split sitemaps: listings, area pages, near pages, static pages. Each one holds at most 50,000 URLs.
- `<lastmod>` is the real content change date, not the build time.
- A video sitemap, or video entries in the listing sitemap, for owner intro videos.
- Regenerated on publish, edit, rented or delete events, not only nightly.
- Submitted to Google Search Console and Bing Webmaster Tools.

### 6. Structured data (JSON-LD)

Google has no rich result for rental listings. Structured data still helps Google understand the page, and some types do earn rich results.

| Page | Types | Rich result? |
|---|---|---|
| Every page | `Organization` (`name` Puascari, `legalName` from settings, `brand` Puascari), `WebSite` (`name` "Sewa Rumah by Puascari") | Site name and logo |
| Listing | `RealEstateListing` containing `Accommodation` (`House`, `Apartment` or `SingleFamilyResidence`), `Offer` (price in MYR per month, `availability`), `numberOfRooms`, `floorSize`, `address` (locality and region only in approximate mode) | No, but helps understanding |
| Listing with intro video | `VideoObject` (`name`, `description`, `thumbnailUrl`, `uploadDate`, `duration`, `contentUrl`) | Yes: video results |
| Listing, area and near pages | `BreadcrumbList` | Yes: breadcrumbs |
| Area and near pages | `ItemList` of listing URLs | No |

- Approximate mode: no `geo`, no street address, and no exact coordinates anywhere in JSON-LD (dev spec E2).
- Never mark up reviews or ratings we don't actually collect.
- Validate with Google's Rich Results Test in CI or as a pre-release step.

### 7. Page content

- **Title:** dev spec D2 template, under about 60 characters. Example: "3-bed terrace, SS2 PJ · 6 min walk to LRT".
- **Meta description:** summary sentence plus price plus a key fact, under about 155 characters. Unique per page.
- **Listing page body:** price, rooms, size, furnishing, availability date, owner intro, nearby rows and owner description, all as real text.
- **Area and near pages:** a short platform-written intro (2 to 3 sentences, generated from real facts such as homes count, price range and nearest rail), then listings. No filler text.
- **Internal links:** listing to area page, listing to its 3 nearest "near" pages, listing to similar homes. Area pages link to neighbouring areas. Breadcrumbs are on every page.
- **Duplicates:** the admin duplicate checker (in the mocks) also prevents duplicate URLs. Merged duplicates 301 to the kept listing.

### 8. Images and video

- Pipeline per dev spec B8: responsive variants, WebP/AVIF, `srcset`/`sizes`, EXIF stripped, descriptive alt text.
- Image file names are readable (`{slug}-kitchen-1.webp`), not hashes, where the CDN allows it.
- The cover is eager-loaded with `fetchpriority="high"`. All other images are lazy-loaded.
- Owner intro video: each video gets its own crawlable thumbnail and a stable URL. A captions file (WebVTT) is always present (dev spec B7). The transcript is rendered as text on the page, which also helps accessibility.
- OG and Twitter card tags on every public page. The OG image is the cover with the crop applied (dev spec B10). This matters for sharing on WhatsApp and Facebook, which is how many Malaysians pass listings around.

### 9. Speed (Core Web Vitals, mobile)

| Measure | Target (75th percentile, mobile) |
|---|---|
| LCP | 2.5 s or less |
| INP | 200 ms or less |
| CLS | 0.1 or less |

- Measured on real users (web-vitals library, sent to our own analytics) and in CI (Lighthouse budget on listing, area and home pages).
- The map and nearby map load only when scrolled into view or tapped. Map scripts are never in the critical path.
- Fonts are self-hosted with `font-display: swap`, at most 2 weights.
- Images and video are served from a CDN with a Singapore or Malaysia edge.
- A JavaScript budget is set for public pages, enforced in CI.

### 10. Privacy (non-negotiable)

- Tenancy records, agreements, move-in media, renter contact details, lead details and payment pages are never indexable or linkable without auth. Signed, expiring URLs are used for downloads.
- Approximate-mode listings expose no exact location in HTML, JSON-LD, map tiles, image EXIF or the sitemap.
- Owner phone numbers are never in public HTML. Contact goes through the enquiry flow.

### 11. Measurement

- Google Search Console and Bing Webmaster Tools are verified before launch.
- Analytics events: organic landing, enquiry sent, and landlord sign-up, each tagged with the landing page type (listing, area, near).
- A monthly SEO report goes to the admin: organic visits, top queries, indexed page count, Core Web Vitals and organic-sourced enquiries.

- [ ] `robots.txt` and the sitemap index are live, and the sitemap is submitted

### 13. AEO and GEO (answer engines and AI chat tools)

Goal: be the source that Google's AI Overviews and AI chat tools (ChatGPT, Gemini, Perplexity, Claude) quote and link.

**13.1 Quick facts box (every listing)**
- A server-rendered "At a glance" block near the top of the listing, marked up as a `<dl>`. It holds rent (RM per month), deposit, bedrooms, bathrooms, size, furnishing, available-from date, and walk time to the nearest rail station.
- A matching one-sentence summary in plain text, for example "3-bed terrace in SS2, Petaling Jaya, RM1,850 a month, 6 minutes' walk to LRT Taman Paramount, available 1 December 2026."
- Values must match the JSON-LD exactly (section 6). Missing values are left out, never shown as "N/A" (dev spec A5).

**13.2 Questions answered with our data (area and near pages)**
- Show 3 to 5 questions as real headings with short answers, generated from live listing data. Examples:
  - "How much is rent near LRT Kelana Jaya?" Answer: median and range.
  - "How many homes are for rent direct from owners here?"
  - "How far are homes from the station?" Answer: typical walk time.
- Every answer states its basis, for example "Based on 12 homes listed on Sewa Rumah, updated 27 October 2026."
- Only shown on pages that pass the N ≥ 5 threshold (section 4). Answers are recomputed when listings change.
- No `FAQPage` rich result is expected (Google limits it to government and health sites). Plain headings and text are what count here.

**13.3 Let AI search tools read public pages (`robots.txt`)**
- Allow search and user-fetch crawlers on public paths: `Googlebot`, `Bingbot`, `OAI-SearchBot`, `ChatGPT-User`, `PerplexityBot`, `Claude-SearchBot` and `Claude-User`.
- Private paths stay disallowed for every crawler (section 4).
- AI training crawlers (`GPTBot`, `ClaudeBot`, `CCBot`, `Google-Extended`) are also allowed on public paths. Public listings are meant to be found, and appearing in training data helps AI tools recognise the brand.
- Review the crawler list every quarter, because names change.

**13.4 About and trust page**
- `/about`, linked from every page footer. It covers:
  - Operator: the legal entity and its company registration number (both from settings). Brand: Puascari. Service: Sewa Rumah.
  - How listings are checked (duplicate check, owner verification), and how to report a listing.
  - Contact email, and the response time for enquiries.
- `Organization` JSON-LD links to this page (`url`) and to official social profiles (`sameAs`), once they exist.

### 14. Later (not at launch)

- **Malay version (parked):** `/ms/` URLs, `hreflang`, Malay "near" and area pages ("rumah sewa dekat ..."). This is the biggest SEO win waiting.
- Chinese (`zh-MY`) version
- Guides and content hub ("How to rent without an agent", "Tenancy agreement checklist Malaysia"). These are strong for "rent without agent" searches, but they need someone to write them regularly.
- Price-range pages per area
- `hreflang` for other markets, if the platform expands (the dev spec already has Netherlands data)
